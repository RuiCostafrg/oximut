# M1 correctness reference

M1 runs a passing baseline, then one static mutant at a time through a fresh
Node/Vitest controller. A Vite plugin serves the transformed module in memory;
Oximut never rewrites the selected source file. With mutations disabled the
transform is the identity operation. Persistent workers, mutation switching,
coverage-based selection, caching, and resource admission remain later milestones.

The operator set is boolean literal inversion (`true` ↔ `false`), comparison
boundary changes (`<` ↔ `<=`, `>` ↔ `>=`), and arithmetic replacements
(`+` ↔ `-`, `*` ↔ `/`). Oxc identifies expression nodes before the operator token
is replaced; comments and strings are not searched for mutation candidates.
Type-only syntax, declaration files, ambient declarations, enums, namespaces,
and decorator expressions are excluded. Unsupported contexts produce diagnostics.
Locations use zero-based UTF-8 byte offsets and one-based lines/UTF-16 columns.
IDs hash root-relative source identity, content, location, operator, and replacement.

Use the pinned Linux Node and Rust toolchains documented in the README:

```sh
npm ci
cargo build -p oximut-cli --locked
target/debug/oximut --root fixtures/m1 \
  --config vitest.config.ts \
  --source src/subject.ts --report .oximut/m1.json
```

The acceptance fixture deliberately produces two killed mutants and one survivor,
so this command exits **1**. Use `--list` to inspect deterministic generated code,
locations, and source maps without executing tests. Repeat `--source` to select
more files. `--baseline-only` runs the original behavior without activating a
mutation. `--timeout-ms` sets the per-job deadline. `--adapter` selects an explicit
adapter entrypoint; the default is the adapter in this source checkout.
Relative source and config paths are resolved against `--root`; report and adapter
paths are resolved against the working directory.

## Outcomes and exit status

Reports use schema version 1 and include baseline evidence, mutant identities,
locations, test counts, errors, and summary counts. Text is printed to stdout;
`--report` writes JSON. Each adapter request and response carries protocol version
1, run ID, job ID, and worker generation. Requests and responses use separate
bounded files so test logging cannot become protocol data.

| Outcome | Meaning |
| --- | --- |
| killed | A valid mutant run completed with failing tests. |
| survived | The full suite completed successfully with the mutant active. |
| no-coverage | Reserved; M1 does not collect sound per-mutant coverage. |
| invalid | Parsing or transformation failed. |
| timeout | The job exceeded its deadline. |
| infrastructure-error | Execution or protocol evidence was unreliable. |
| skipped | No successful execution evidence was obtained. |

The score is `100 × killed / (killed + survived + no-coverage)`, or `null` for
an empty denominator. Invalid, timeout, infrastructure-error, and skipped results
are excluded and make a mutation run incomplete. Timeouts are never counted as
kills. Uncalled code can therefore survive in M1; absence of test failures is not
proof of coverage.

Exit **0** means a complete run without survivors (or a successful baseline-only
run), **1** means a complete run with survivors, and **2** means a configuration,
baseline, or incomplete execution error. No score threshold is applied.
Source generation errors are reported on stderr before execution begins; no run
report is produced when generation cannot finish. Failed baselines leave planned
mutants explicitly skipped.

## Validation and limitations

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build -p oximut-cli --locked
npm run format:check
npm run lint
npm run typecheck
npm test
python3 -m unittest discover -s tests -v
```

The M1 fixture asserts known kills and a survivor, stable generation, report
semantics, and unchanged source bytes. The stateful fixture exercises imports,
mocks, hooks, async tests, and module state with mutations disabled and verifies
that all four service mutants are killed under fresh execution. Adapter tests
cover malformed protocol, transform failures, and process deadlines; Rust tests
cover generation and report/protocol semantics.

The current execution reference requires Linux and Python for process-tree
supervision, Node 26.3.1 and Vitest 4.1.12. Supported source scope is deliberately
narrow JS/TS ESM. TypeScript semantic checking, browser projects, coverage
selection, and performance claims are outside M1. Source maps describe the static
replacement and are passed to Vite for composition.

The local checks also cover an Android-target Rust binary inside Linux PRoot;
its watchdog uses the same Linux-kernel process supervision. Node must still be
the Linux executable in this setup. Module-level runtime errors and unsupported
execution failures are conservatively infrastructure errors rather than kills.
