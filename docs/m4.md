# M4 — Reliable incremental cache

Caching is opt-in. Instrumentation artifacts and mutation outcomes use separate
stores, so a change to tests can invalidate execution evidence without requiring
unchanged sources to be instrumented again.

```sh
cargo build -p oximut-cli --locked
target/debug/oximut --root fixtures/pure --config vitest.config.ts \
  --source src/logic.ts --cache --cache-inputs-complete
```

`--cache` enables instrumentation caching. Outcome caching additionally requires
`--cache-inputs-complete`: an explicit assertion that all inputs affecting test
behavior are tracked and that no undeclared nondeterministic external inputs
remain. Do not make that assertion for tests depending on uncontrolled time,
randomness, network services, or external state. Instrumentation caching remains
available without it.

Declare additional files or directories with repeated `--cache-input FILE` arguments, and
relevant environment variables with repeated `--cache-env NAME` arguments.
All inherited environment values are conservatively included too, so changes to
unrelated environment variables can cause misses. Environment values are hashed;
raw values are not recorded in cache metadata or reports. These declarations track inputs, not service availability
or the behavior of a remote system.

`--no-cache` (also `--force`) bypasses cache reuse and persistence. Use it to
compare a cached run against newly executed mutation results.

Every execution still runs the unmutated baseline. Persistent execution retains
its disabled-switch validation, and test selection retains its coverage baseline
and conservative attribution checks. Cached outcomes are never a substitute for
these validations.

The initial execution fingerprint is project-wide. Dependency-granular outcome
reuse is deferred until dependency graph completeness can be established.

The stores live in `ROOT/.oximut/cache/instrumentation` and
`ROOT/.oximut/cache/outcomes`. Cache files carry a schema version and completion
marker. Writes use a temporary file followed by an atomic rename. Orphaned
transaction files are ignored, and unreadable, corrupt, or incompatible entries
are misses. An incomplete execution cannot publish a new reusable outcome bundle;
a previously completed bundle remains independent of a later failed run.

The fingerprint includes project file contents, ancestor package manifests and
lockfiles, installed dependency contents, adapter behavior, the runner binary,
Node identity and executable launcher, execution settings, and declared inputs.
Runtime caches and the report output are reserved outputs, not supported execution inputs. Specifically,
`.oximut/cache`, `.git` directories, `node_modules/.vite`,
`node_modules/.vite-temp`, and the report destination are excluded. Do not depend
on those paths as test inputs; explicitly declaring an excluded input disables
outcome caching. Imports or external files outside the tracked trees must be
declared. Uncertain external symlinks disable outcome caching rather than guessing at their dependencies.

This deliberately prioritizes correctness over cheap lookup: fingerprinting
large projects and installed dependencies can be expensive. M4 makes no measured
performance claim. Fresh execution and full-suite runs remain the correctness
references, and M2/M3 isolation and test-selection limitations still apply.

JSON reports add a `cache` object with the execution fingerprint, outcome-cache
eligibility/reason, instrumentation and outcome hit/miss counts, and persistence
state. Each mutant has `provenance` identifying fresh execution, baseline
coverage, a skipped result, or cache reuse; reused results identify the prior
run. The JSON persistence state records a staged transaction: publication follows
successful report emission. Text output records the final commit result. A
report-write failure drops the staged transaction.

Runtime identity probing has a bounded output and deadline, and cleans up its
process tree. An unavailable or unsafe fingerprint disables outcome caching with
a reason; it does not prevent an otherwise valid uncached test run.

For local acceptance checks on ARM with a debug build, SHA-256 can dominate the
run. The validation command below optimizes that dependency without changing
cache semantics or committing a build-profile setting:

```sh
cargo build -p oximut-cli --locked --config 'profile.dev.package.sha2.opt-level=3'
python3 -m unittest discover -s tests -p 'test_m4.py' -v
```

Validation covers real Vitest cached/forced agreement in fresh and persistent
selection modes, test inventory changes, baseline failures with an available
cache entry, incomplete runs, every declared input category, corrupt entries,
interrupted transactions, and runtime-probe cleanup. Rust tests also cover
runtime/tool/settings fingerprints, payload integrity, external symlinks, and
unambiguous framing of absent versus present environment inputs.
